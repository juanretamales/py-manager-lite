# 05. Especificación v0.1

## Objetivo

Validar Flet como tecnología para una aplicación de escritorio pequeña.

No intentar construir todo el producto en esta fase.

## Funcionalidad mínima

### Navegación

Menú lateral con:

- Inicio
- Mi Empresa
- Clientes
- Cotizaciones
- Proyectos
- Finanzas
- Configuración

Órdenes de compra puede existir como placeholder o integrarse más adelante.

### Inicio

Dashboard simple con datos ficticios o reales de la base:

- cotizaciones abiertas;
- monto cotizado;
- proyectos activos;
- facturas emitidas;
- cobrado;
- facturas recibidas;
- pagado;
- saldo pendiente.

### Mi Empresa

Formulario básico de datos de empresa.

Canvas puede existir inicialmente como vista visual sin funcionalidad completa de edición.

### Clientes

CRUD mínimo:

- crear;
- listar;
- editar;
- desactivar.

Debe existir una vista de detalle.

### Cotizaciones

CRUD inicial:

- crear;
- listar;
- cambiar estado;
- agregar ítems;
- calcular total.

No generar PDF todavía si complica la prueba de Flet.

### Proyectos

- crear proyecto manualmente;
- asociar cliente;
- estado;
- progreso;
- notas.

### Finanzas

Para v0.1 puede bastar con una sola pantalla simple que permita:

- registrar factura;
- indicar tipo emitida/recibida;
- registrar pago;
- calcular saldo.

## Métricas de evaluación de Flet

Registrar manualmente:

- tamaño del ejecutable;
- tiempo de arranque en frío;
- consumo de RAM inicial;
- consumo de RAM con varias pantallas;
- sensación de respuesta;
- facilidad de empaquetado;
- comportamiento de tablas;
- comportamiento de formularios;
- estabilidad de navegación;
- experiencia de desarrollo.

## No implementar en v0.1

- IA.
- Supabase.
- SII.
- autenticación compleja.
- permisos/roles.
- sincronización cloud.
- backups automáticos.
- importación automática de facturas.
- OCR.
- conciliación bancaria.
